# Firmware: AI pipeline (AI-SED 2026, ITESCA PCB Lab)

`src/ai_pipeline.c/.h`: one 1024-sample window (13.333 kHz) -> 22 features -> MLP 22-32-16-4 -> class + probabilities.
Pure C99, no dynamic memory, float32. `include/modelo_pesos.h` is generated by `model/modeloCWRU_corregido.py`.

* On the STM32F411CE build with `-DAI_USE_CMSIS_DSP` (uses `arm_rfft_fast_f32`). Without it a portable FFT is used.
* Status: verified on a PC against the Python reference (`test/`). Not yet flashed or timed on the microcontroller.
* Still to do: SPI driver for the IIS3DWB, 2:1 decimation (26.667 -> 13.333 kHz), USART1 link to the ESP32-C3.

Test (needs the CWRU .mat files): `python3 test/export_ref.py` then
`gcc -O2 -std=c99 -o test/test_pipeline test/test_pipeline.c src/ai_pipeline.c -lm && ./test/test_pipeline`

## app/ - demo firmware for Proteus VSM / the real board
Bare-metal (no HAL) program for the STM32F411CE: startup, linker script, UART on PA9 (USART1, 115200 8N1).
It runs the pipeline on 16 real CWRU windows (3 HP, unseen in training) stored in flash and prints each diagnosis.
Build for the real board (hardware FPU): `arm-none-eabi-gcc -mcpu=cortex-m4 -mthumb -mfpu=fpv4-sp-d16 -mfloat-abi=hard -O2 -T app/stm32f411.ld -Wl,--gc-sections --specs=nano.specs --specs=nosys.specs app/startup.c app/main.c src/ai_pipeline.c -o app/ai_sed.elf -lm` (also `ai_sed.hex`).
Build for Proteus VSM (software floating point, no DWT counter, because Proteus does not model the Cortex-M4 FPU or the DWT): same command with `-mfloat-abi=soft -DNO_DWT -g` and no `-mfpu`, output `app/ai_sed_proteus.elf`.

Status:
* Cortex-M4 CPU emulator (Unicorn): 16/16 correct.
* Proteus VSM (STM32F411CE, Virtual Terminal on PA9, 115200 8N1, Forced HCLK 16 MHz): 16/16 correct, `app/ai_sed_proteus.elf`.
* Not yet flashed or timed on real hardware. The IIS3DWB cannot be simulated, so the windows come from CWRU data stored in flash.
* `app/hello.c`: minimal UART test used to debug the Proteus setup.
